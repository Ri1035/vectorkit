## 一、结论摘要

实验目标：验证「Vector Magic 式轮廓联合优化」能否缩小 vectorkit 与 VM 的差距。

| 方案（1280² 口径） | 段数 | PSNR | 结论 |
|---|---|---|---|
| VTracer `spline`（现行） | 1493 | 32.88 | 基线 |
| VTracer `polygon` 原样 | 4832 | 33.29 | 精度略高、段数 3.2× |
| polygon + RDP 0.35 + 手柄拟合 | 4006 | **33.34** | 唯一略升，但体积 181 KB（spline 34 KB） |
| 四项能量优化（多组权重） | 2604–2730 | 31.69–32.04 | **全部低于不优化** |
| 零权重对照（w=0） | 4006 | **33.34** | 与不优化**逐字节相同** |
| 亚像素目标 + 联合优化 | 2939 | 30.41 | 更差 |

**结论**：

1. 在 VTracer 输出上做任何非零强度的几何平滑/联合优化，都会把像素精确边界推离真值 → **必降质**。
2. 掉分来自平滑项本身，不是实现 bug（零权重对照逐字节相同，`181022 bytes`）。
3. `spline` 的拟合效率仍高于自研 `RDP + 手柄`：1493 段 32.88 dB vs 4006 段 33.34 dB。
4. 与 VM 的差距在**分割 + 亚像素边界**，不在曲线拟合/平滑；继续做几何后处理预期收益为负。
5. `polygon + RDP 0.35 + bezierfit` 只适合“精度优先、体积不设约束”的可选档，且必须处理 cutout 共享边。

> **阶段 2 修正（2026-11-07）**：第 1 条只在**干净边界**（扁平色块）上成立。
> 纹理/做旧类图（`xrk`）上 `polygon` 原样反而 **−2.35 dB**，说明 `spline` 的平滑对噪声边界是正收益。
> 详见 [`handover/2026-11-07/05_阶段2_多图复测.md`](./handover/2026-11-07/05_阶段2_多图复测.md)。

## 二、对项目的影响

| 现有内容 | 交接结论 | 处理决定 |
|---|---|---|
| `refine.js`（重栅格化精修，默认关） | 扁平插画上不成立 | **保持默认关闭，不再推广** |
| `subpx.js` / `subpixel.js` 原型 | 均属“移动锚点”路线 | **不接入生产，文档标注已证伪** |
| `app.js` 的 cutout 跳过几何后处理 | 可推广到所有几何后处理 | 行为不变，补文档说明 |
| `bezierfit.js` | 唯一值得复用的拟合器 | 需要时补“开放段拟合”出口，不重写 |
| `PLAN_PARALLEL_ENGINE` 的 P2' | 与 VTracer 后处理无关 | 保留为独立分割引擎方向，**不复用 vm_smooth 到 VTracer 输出** |

> 工程风险（N8）：本轮 polygon 实验的 options 写了 `cutout`，但产物是逐 path 独立几何。
> **生产接入前必须建共享边对应表并验证不撕缝**，否则会复现“MSE ×46”的 cutout 撕裂问题。

### 阶段 2 · 多图复测（✅ 2026-11-07 完成，未改产品代码）

测试图 4 张（`bc` 1280² 扁平插画 / `h` 366×375 曼陀罗线稿 / `x` 593×807 扁平冬季 / `xrk` 475×410 颗粒纹理），
方案 A=`spline`、B=`polygon` 原样、B2=B+RDP 0.35+角点保护手柄拟合。

| 图 | A spline | B polygon | B2 重拟合 | 关键判定 |
|---|---|---|---|---|
| bc | 32.88 | **33.29** | 33.28 | 复现交接数字（B2 差 0.06 dB） |
| h | **16.66** | 16.41 | 16.50 | 线稿上 spline 更好 |
| x | 29.70 | **30.18** | 28.37 | B2 **−1.81 dB**，并新增 1129 白缝像素 |
| xrk | **24.18** | 21.83 | 23.86 | 纹理图上 polygon **−2.35 dB** |

**验收结果**：

1. ✅ 交接数字复现（A/B/B2 与交接书一致）
2. ❌ B2 四图全败（最好持平，最差 −2.03 dB）→ **阶段 3 不批准**
3. ✅ cutout 共享边已量化：polygon 输出 92.2–95.9% 的边被 ≥2 条子路径共用；
   逐路径重拟合后锚点重合率 99.7% → 96–97%，`x` 白缝 0 → 1129 像素 → **N8 撕边风险实测成立**
4. ⚠️ 发现 `ssimEdge` 产出 >1 的退化值（`h` B2 = 1.97、`xrk` B = 11.03）→ 已登记为待修
5. ✅ 结论细化为「**对干净边界无效且有害；对噪声边界方向可能反转**」

### 阶段 2b · 描摹分辨率档位复测（✅ 2026-11-07 完成，v7.8）

| 图（尺寸） | ×1 | ×2 | ×3 | ×4 |
|---|---|---|---|---|
| mandala（366×375 线稿） | 16.66 | 18.28 | **20.38** | — |
| winter（593×807 扁平） | 29.70 | **30.28** | 27.70 | 26.30 |
| sunflower（475×410 纹理） | **24.18** | 24.05 | 23.76 | — |

**结论**：

1. **×2 是唯一「基本不亏」的档位**（+1.62 / +0.58 / −0.13 dB + ssimEdge 提升）→ 现有「自动 ×2」默认保持不变
2. **×3 只在低分辨率线稿上大幅获益**（mandala +3.72 dB、ssimEdge +0.28），
   代价：碎块分 2744→6972（2.5×）、新增 507 白缝、体积 5.7×、耗时 ×19
3. **×3/×4 在扁平与纹理图上明确降质**（winter −2.00 / −3.40 dB），
   虽然 jag 更低（更平滑）→ 又一份「平滑 ≠ 更准」证据
4. **UI 措辞待决策**：`×3（最细 · 慢）` 会误导为「必然更好」，实测并非如此

证据：[`handover/2026-11-07/06_分辨率档位复测.md`](./handover/2026-11-07/06_分辨率档位复测.md)
