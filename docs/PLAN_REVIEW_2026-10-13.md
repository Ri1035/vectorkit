# 计划审查报告（2026-10-13）

> 触发：用户指出"目标是压体积，但一定要压吗？" —— 复查发现**计划里存在没有依据的假设**，
> 且**已有证据显示主指标与用户观感脱钩**，却仍在沿用。
> 本报告逐条列出站不住脚的地方、证据与处置，并确立修正后的指标体系与纪律。
> 关联：`PLAN_HIGH_FIDELITY.md`（主线）、`PLAN_PARALLEL_ENGINE.md`（并列引擎）

## 一、审查结论摘要

发现 **9 处站不住脚或已失效的前提**，其中 3 处会**直接误导下一步决策**（已修正）。
最严重的一条不是"体积目标错了"，而是 **"用 PSNR 代表保真度/观感"这个前提本身已被项目实测证伪**。

## 二、逐条审查

### ❌ 1. "压体积"是用户痛点 —— **无任何依据**（已撤销）

- **证据**：用户自 v5.3 以来的全部反馈是"丢失明显 / 边缘锯齿 / 碎块多 / 按钮卡死 / 模板不切换"，
  **从未提及体积**。现行 VTracer 默认档 29–80 KB、以及早前 24557 节点的输出，用户都一直在用。
- **技术事实**：拟合越激进（体积越小）→ PSNR 越低。实测 err 0.9 → 31.60、err 0.4 → **31.76**，
  方向是**保真度与体积相反**。原 P2"265KB → 几十 KB"是**用保真度换体积**。
- **处置**：**撤销 P2 的体积目标**，改为「保真度优先、容差寻优」。
- **用户确认（2026-10-13）**："体积约束：无所谓不用特意控制" → **体积彻底不设约束**，
  既不为体积牺牲保真度，也不为"精简"主动放宽容差。**唯一目标是保真度与观感。**

### ❌ 2. "PSNR 可以代表用户观感" —— **已被本项目实测证伪**（最重要）

- **反例（v5.3）**：把去噪 14→8 后，**PSNR 提升 +2.86 dB**，但用户反馈
  **"边缘锯齿明显了，没有上一版平滑"** —— 即**客观指标变好、主观观感变差**。
- **根因**：PSNR 对**碎块**几乎不敏感（少量碎块像素对全局 MSE 贡献极小），
  对**边缘锯齿**的惩罚也不等同于人眼感受。
- **处置**：确立 **观感指标为一等公民**（见第三节），PSNR 降级为"不回归"的守门指标。

### ⚠️ 3. M1 门槛 = "基线 + 1 dB" —— 任意且会漂移

- **问题**：1 dB 从何而来没有依据；且"基线"随默认参数调整而变（v5.3 已改过一次），门槛随之漂移。
- **处置**：门槛改为**锚定具体数值 + 注明测量口径**（图、尺寸、引擎、参数），并写明"基线变更时必须重述门槛"。

### ⚠️ 4. "已排除清单"缺少排除时的配置

- **问题**："逐点亚像素无收益""样条参数无效"等结论，是在**当时的默认参数**下测得的；
  默认参数此后已改（v5.3 去噪 14→8、v5.4 恢复 simplify），却没记录排除时的配置。
- **风险**：未来可能拿旧结论否定新配置下的可能性。
- **处置**：每条"已排除"必须附**排除时的引擎/参数/图/尺寸**。

### ⚠️ 5. "原型的改进可直接迁移到生产"

- **问题**：`subpx.js` / `bezierfit.js` 是**独立代码路径**，未接入 `app.js` 的后处理、
  SVGO、EPS/DXF 导出、CorelDRAW 兼容（legacy）模式。原型上的任何结论**都未在生产链路上验证过**。
- **处置**：原型结论一律标注"**未接入生产链路**"；若要上线，需单独做接入与回归。

### ⚠️ 6. "锯齿指数"指标方向是错的 —— 但曾被用来指导决策

- **问题**：v5.4 自造的"锯齿指数"（转角>25° 锚点占比）在 `simplify` 生效时**上升**，
  而视觉上是更平滑 → **指标与被测量对象反向**。
- **处置**：在计划中标注该指标**已废弃**，禁止再用；若要测锯齿必须先验证指标方向。

### ⚠️ 7. 计划文档状态长期失真

- **问题**：`PLAN_JOINT_OPTIMIZATION.md` 长期停在"待用户测试 v5.4 后启动"，
  而其核心结论早在 v5.2 / v5.6 / v6.1 就被推翻 → 读者可能据此启动已被证伪的方案。
- **处置**：建立**计划状态总表**（第四节）作为单一事实来源；各计划文档头部必须标注状态与取代关系。

### ⚠️ 8. 默认参数变更未留基线快照

- **问题**：v5.3 把默认去噪 14→8、切 cutout、去掉 simplify，但没有保留"改前"的可复现配置，
  一旦效果回退难以定位是哪次改动导致。
- **处置**：每次改默认参数，必须在 CHANGELOG 记录**改前 → 改后**的对照值（已有），并在
  `check-presets.cjs` 固化基线断言（已有）。

### ⚠️ 9. 指标测量口径与生产口径不一致（需注明而非修正）

- **情况**：所有横向对照都在 **1024² 栅格**上测量（VM 的 viewBox 即 1024，属同口径），
  但生产默认对 bc.png（2048² 原图）是**按 2048 描摹**。
- **风险**：读者可能把 1024² 上的 PSNR 当成生产输出质量。
- **处置**：所有指标必须标注**测量口径**（输入尺寸 / 渲染尺寸），并在计划首页声明。

## 三、修正后的指标体系

### A. 客观指标（守门用，**不得作为唯一目标**）

| 指标 | 作用 | 注意 |
|---|---|---|
| PSNR / MSE | 防止**明显回归** | 对碎块、锯齿不敏感 |
| 白缝 / 白点像素数 | 印刷与拼接观感 | 现有指标，可靠 |
| 路径数 / 命令数 / 体积 | 可编辑性与切割机友好 | **不设约束**（用户 2026-10-13 确认"不用特意控制"） |

### B. 观感指标（一等公民，**缺失即不得下结论**）

| 观感诉求（用户原话） | 可量化代理 | 现状 |
|---|---|---|
| **不要丢失细节** | 与源图的**局部结构相似度**（如边缘图 SSIM）；细节像素的检出率 | 缺 |
| **边缘要平滑、不要锯齿** | ⚠️ 必须**先验证指标方向**（见第 6 条）；候选：轮廓法向的**高频能量**（越高越锯） | 缺 |
| **不要过多碎块 / 切色块** | 小面积区域数 + **与邻色区域的色差加权**（贴近背景色的小块才算碎块） | 有雏形，需加权 |
| **内部元素不要丢**（眼白/高光） | 指定 ROI 内的颜色还原率 | 有专项排查记录 |

> **纪律**：任何"更好/更差"的结论，必须同时给出 **客观指标 + 至少一个观感代理**；
> 只有 PSNR 变化时，**不得**写进 CHANGELOG 的结论行。

## 五、纪律（防止再犯低级错误）

1. **目标必须来自用户诉求**，不得由"看起来像优化项"推导（本条的由来：体积）。
2. **指标先验证方向再使用**（锯齿指数教训）。
3. **结论必须标注测量口径与基线配置**（1024² vs 2048；哪个参数组）。
4. **"已排除"必须附排除时的配置**，否则不得直接引用。
5. **客观指标不得单独支撑结论**，须配观感代理。
6. **原型结论默认"未接入生产"**，不得直接当作产品结论。
7. **计划文档状态必须与总表一致**，发现失真立即修正（PLAN_JOINT_OPTIMIZATION 教训）。
8. 改默认参数必须留**改前 → 改后**对照，并固化进 `npm test` 断言。
