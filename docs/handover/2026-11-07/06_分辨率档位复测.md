> 目的：量化「描摹分辨率 ×2 / ×3 / ×4」的收益与代价，检验「提高分辨率是最有效杠杆」这一旧结论的边界。
> 口径：白底合成 → BICUBIC 上采样 → VTracer `logo` 档（`opt_logo.json`）→ resvg **按原始尺寸**栅格化
> → 与原始尺寸参考图逐像素比较。
> 说明：浏览器内上采样用 `canvas.imageSmoothingQuality='high'`，本实验用 PIL BICUBIC 近似。

## 二、结论

### 2.1 ×2 是唯一「基本不亏」的档位

| 图 | ×2 相对 ×1 |
|---|---|
| mandala | **+1.62 dB**，edgeCorr +0.098，ssimEdge +0.120 |
| winter | **+0.58 dB**，edgeCorr +0.063，碎块分 −1% |
| sunflower | −0.13 dB（噪声级），但 ssimEdge +0.039、edgeCorr +0.034 |

当前默认「自动（短边 < 800px 时 ×2）」在四张图上均无害，**保持不动**。

### 2.2 ×3 只在「低分辨率线稿」上大幅获益

`mandala`（366px 短边、细线）在 ×3 上 **+3.72 dB**、ssimEdge **+0.28**、edgeCorr **+0.22**，
是本次全部实验中单项收益最大的一组 —— 因为细线在 366px 下本就欠采样。

**代价同样明显**：碎块分 2744 → **6972（2.5×）**，并新出现 **507** 个白缝像素，体积 118 → 678 KB，耗时 ×19。

### 2.3 ×3 / ×4 在扁平与纹理图上明确降质

| 图 | ×3 | ×4 |
|---|---|---|
| winter（扁平） | **−2.00 dB** | **−3.40 dB** |
| sunflower（纹理） | −0.42 dB | — |

其中 winter 的 `jag` 从 38.3 一路降到 27.4（更平滑），但 PSNR 一路下降 ——
**又一份「平滑 ≠ 更准」的证据**：高倍上采样让边缘被引擎磨平，反而偏离真实边界。

### 2.4 对现有 UI 的影响（待决策，本轮未改）

界面「描摹分辨率」里 `×3（最细 · 慢）` 的措辞会让人以为必然更好。实测表明：

- 只在**短边 ∼400px 以下的线稿/印章**上值得用
- 在**扁平色块与纹理图**上会掉 0.4–3.4 dB，且碎块数上升

## 三、口径警示

- `jag` 降低可能来自「平滑」而非「更准」：winter ×4 的 jag 最低（27.4），但 PSNR 也是最低（26.30）。
  **不得用 jag 单独判断分辨率档位优劣。**
- `mandala` 的 PSNR 绝对值偏低（16–20 dB）是**小尺寸 + 细线**共同导致的：细线在 366px 下大部分被
  `filterSpeckle 10` 抹掉，属于预期行为，不代表引擎异常。
- 与项目旧结论的口径差异：旧的「×2 得 +3.15 dB」测的是 Bon Cho 1280²（大图、扁平），
  本轮 ×2 在 366–593px 小图上得 +0.58~+1.62 dB。**同一档位在不同原图尺寸下不可直接比较**。

## 四、复跑方法

```powershell
cd C:\Users\Administrator\Desktop\svg\_work\scripts

# 上采样 raw（参考图始终是原始尺寸）
python prep_scale.py ..\..\交接\x.png 3 ..\out3\winter_s3.raw ..\out3\winter_ref.png

# 按原始宽度渲染，保证与参考图同口径
node pipeline.mjs ..\out3\winter_s3.raw 1779 2421 ..\out3\winter_s3.svg ..\out3\winter_s3.png ..\out\opt_logo.json 593

python compare.py ..\out3\winter_ref.png ..\out3\winter_s3.png "winter x3"

# 观感指标
python png2raw.py ..\out3\winter_s3.png ..\out3\winter_s3.raw
node perceptual-eval.mjs ..\out3\winter_ref.raw ..\out3\winter_s3.raw 593 807
```

> PowerShell 变量名**不区分大小写**（`$w` 与 `$W` 是同一个变量），批量脚本里必须用不同名字，
> 否则循环第二轮起尺寸会串（本轮踩过一次）。
