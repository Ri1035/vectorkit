## 2. 核心：让 vendor 的 wasm 在 Node 里加载

`vectorkit/vendor/vtracer.js` 的 `initVtracerWasm()` 用 `fetch(new URL('...wasm', import.meta.url))`，
Node 的 fetch 不支持 `file://`。**在 import 之前**打补丁：

```js
import fs from 'node:fs/promises';

const realFetch = globalThis.fetch;
globalThis.fetch = async (input, init) => {
  const url = input instanceof URL ? input : new URL(typeof input === 'string' ? input : input.url);
  if (url.protocol === 'file:') {
    const buf = await fs.readFile(url);
    return new Response(buf, { status: 200, headers: { 'Content-Type': 'application/wasm' } });
  }
  return realFetch(input, init);
};

const { initVtracerWasm, vectorize_rgba } = await import('../../vectorkit/vendor/vtracer.js');
await initVtracerWasm();
```

`resvg` 用另一种方式（接受 buffer）：

```js
const mod = await import('file://' + resvgMjsPath.replace(/\\/g, '/'));
await mod.initWasm(await fs.readFile('.../resvg_bg.wasm'));
const png = new mod.Resvg(svg, { fitTo: { mode: 'width', value: 1280 }, background: 'white' })
                .render().asPng();
```

> 注意 `import()` 的路径必须是 `file://` URL，Windows 反斜杠要转正斜杠。

## 3. 复跑全流程

```powershell
cd C:\Users\Administrator\Desktop\svg\_work\scripts

# ① 准备输入
python prep.py "C:\Users\Administrator\Downloads\test.jpg" ..\out\test_rgba.raw ..\out\test_ref.png
```

`options` 文件示例（`out/opt_logo.json`）：

```json
{"clustering":"color-cluster","hierarchical":"cutout","mode":"spline",

 "cornerThreshold":60,"lengthThreshold":4,"maxIterations":10,"pathPrecision":1}
```

`mode` 改成 `"polygon"` + `pathPrecision: 2` 就是本轮实验用的折线模式。

## 4. 五个坑（都踩过）

### 坑 1 · wasm 加载
见第 2 节。症状：`fetch failed`。

### 坑 2 · PowerShell 吃掉 JSON 引号
`node x.mjs '{"a":"b"}'` → Node 收到 `{a:b}` → `JSON.parse` 报错。
**解法**：options 写文件，脚本读文件（`pipeline.mjs` 已改成这样）。

### 坑 3 · PowerShell 不支持 heredoc
`python - <<'PY'` 直接语法错误。
**解法**：写成 `.py` 文件再跑；或 `python -c "..."`（但内嵌双引号又会被吃）。

### 坑 4 · `Set-Content -Encoding utf8` 毁 Python 源码
用它改 `.py` 文件会把中文注释变成私用区字符（U+E746…），Python 报
`SyntaxError: invalid non-printable character`。
**解法**：用编辑工具改，不要用 shell 重写源码。

### 坑 5 · PIL `save('x.raw')`
`unknown file extension: .raw`。
**解法**：`open(path,'wb').write(im.tobytes())`。

## 5. 度量脚本口径

`compare.py` 做三件事：

```python
MSE  = mean((ref - out)^2)                      # RGB 三通道
PSNR = 10*log10(255^2 / MSE)
seam = count(ref非白 & out接近纯白)              # 白缝
edgeCorr = corr(sobel(ref), sobel(out))         # 结构保真代理
```

**注意**：
- 参考图必须与渲染口径一致（都用白底合成、都 1280 宽）
- `edgeCorr` 是相关系数，范围 [-1,1]，越高越保结构
- 这三个指标要一起看，**PSNR 单独不足以判断观感**（项目 `PLAN_REVIEW` 已确立的纪律）

## 6. 如果再要测别的图

```powershell
python prep.py <新图> ..\out\new_rgba.raw ..\out\new_ref.png
node pipeline.mjs ..\out\new_rgba.raw <W> <H> ..\out\new.svg ..\out\new.png ..\out\opt_logo.json <W>
python compare.py ..\out\new_ref.png ..\out\new.png "new"
```

**建议至少测三类图**（本轮只测了扁平插画）：

| 类型 | 为什么 |
|---|---|
| 扁平插画 / Logo | 本轮结论只在类上成立 |
| 照片 / 渐变 | 平滑可能**有益**（边界有噪声），结论可能反转 |
| 扫描线稿 / 文字 | 检验细笔画的保真 |

## 7. 已知未验证项

- **照片类**：本轮完全没测。`vm_smooth` 在"有噪声的边界"上可能真的是正收益（参考实现里
  阶梯轮廓的径向 RMS 从 0.286 降到 0.093）。**要下"优化层无用"的总结论，必须先补这一类。**
- **cutout 共享边界**：本轮用的是 polygon 的独立路径，没触发撕裂问题。
  生产链路是 cutout，若要接入几何处理，必须先建共享边对应表。
- **2× / 3× 分辨率**：本轮未测（项目已测 2× 得 +3.15 dB）。
