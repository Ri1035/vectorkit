# 对照文档：Vector Magic 桌面版（软件） vs vectorkit（Web 应用）

> 目的：把"参考软件"与"我们自己的项目"在**架构、算法、精度机制、能力、代价**上逐项对照，
> 明确**差距在哪、差距有多大、哪些差距是刻意的取舍**。
> 依据：本轮对 `vmde.exe` 的静态 + 动态取证、公开论文（Diebel 2008）、以及本项目的**实测数据**。
> 日期：2026-10-12

---

## 一、身份与形态

| 维度 | Vector Magic 桌面版（软件） | vectorkit（Web 应用） |
|---|---|---|
| 载体 | Windows 原生程序（本次样本 `vmde.exe`） | 纯静态网页（https://vectorkit.pages.dev） |
| 技术栈 | **Qt 4.4.3**（GUI/IO）+ **Netlib BLAS/LAPACK**（数值）+ MSVC 7.1 | 原生 ESM + **VTracer/Potrace/resvg/SVGO/Paper.js**（全 WASM/JS） |
| 运行方式 | 需安装、离线可用、本机算力 | 浏览器内运行、**不上传服务器**、跨平台 |
| 分发 | 商业授权（订阅/买断） | 开源、免费、可自托管 |
| 体量 | 整包约 21MB（`vmde.exe` 6.5MB + Qt/BLAS/LAPACK 等） | 整包约 4.7MB（含 4 个 WASM/JS 引擎） |

**本轮动态取证（用户实机启动后观测）**：
- 进程 `vmde.exe`，PID 9680，窗口标题 **`bc.png - Vector Magic Desktop Edition`**
  → **`vmde.exe` 就是主程序本体**（不是引擎辅助进程；该 repack 目录即整套程序）。
- **无监听端口**（非 socket/服务型引擎），常驻内存 271MB。
- 保护：**Themida/WinLicense 2.0.1–2.1.8**（引擎）+ **VMProtect 1.70 Max**（`QtCore4.dll`）；
  TLS 回调、随机节名、`int3` 自修改引导桩、资源仅剩图标。

## 二、算法类别（**决定"为什么它慢、为什么它准"**）

| 维度 | Vector Magic | vectorkit |
|---|---|---|
| 范式 | **概率反问题**：把抗锯齿光栅化建成可微生成模型，用贝叶斯求矢量图的 **MAP 估计** | **确定性管线**：预处理 → 引擎描摹 → 优化/后处理 |
| 求解 | **混合连续-离散优化**：离散阶段定形状/颜色/拓扑 → **连续阶段用非线性共轭梯度**定精确边界 → 三次贝塞尔拟合 | **单遍前馈**：**无迭代优化循环** |
| 变量规模 | 约 10⁴ 连续 + 10⁵ 离散 | 无（一次成型） |
| 精度来源 | **反解抗锯齿覆盖率 → 亚像素边界** | 引擎的颜色聚类 + 后处理曲线拟合 |
| 依赖 | 需要 **LAPACK/BLAS**（共轭梯度 = 稠密线性代数） | 不需要（线性时间引擎） |
| 实测耗时（Bon Cho 1280²） | —（未做同口径测量） | **805ms**（基线）/ 2.1s（描摹 ×2） |

> 结论：**它不是"优化得比我们好"，而是"根本不是同一类算法"。**
> 我们的速度来自"做一次"，它的精度来自"反复迭代到收敛"。

## 四、输出质量：**我们自己的实测**（Bon Cho 1280×1280）

在同口径（把输出 SVG 栅格化回原尺寸、白底合成、与原图逐像素比）下测得的**量化结果**：

| 配置 | 输入 | 合计耗时 | anchors | 体积 | MSE↓ | PSNR↑ | 白缝/白点 |
|---|---|---|---|---|---|---|---|
| v4.3 基线 | 1280 | 805ms | 2583 | 65.6KB | 51.52 | 31.01 dB | 11 |
| **描摹 ×2** | 2560 | 2077ms | 8109 | 207.9KB | **24.15** | **34.30 dB** | 7 |
| ×2 + `simplify 1` | 2560 | 1635ms | 3711 | 93.4KB | 25.33 | 34.09 dB | 5 |
| ×2 + `vmde`(cutout) | 2560 | 2098ms | 4638 | 120KB | 24.29 | 34.28 dB | 8 |
| ×2 + 去噪 | 2560 | 2520ms | 6814 | 177.7KB | 26.35 | 33.92 dB | **0** |

**三条实测修正**（详见 `docs/CHANGELOG.md` [4.7]）：
1. **`simplify` 在本图降质**（MSE +7.4%）→ 它换体积/节点，不换质量；默认必须保持 **0**。
2. **`cutout` 在 1× 下更准（MSE −18%）但白缝 11→40**；到 2× 后转为"**同质量、节点 −44%、体积 −42%**"。
3. **分辨率是最大杠杆**：×2 → **MSE −53%、PSNR +3.3dB、白缝更少**。

### ✅ Vector Magic vs vectorkit：同图同口径实测（2026-10-13）

**材料**：用户从 Vector Magic 桌面版导出 `bc.svg` / `bc.ai` / `bc.eps`
（原图 `bc.png` **2048×2048**）。双方输出与**同一张原图**在 **1024×1024** 栅格下逐像素比较
（白底合成、比 RGB）：MSE / PSNR / 锚点数 / 体积 / 白缝。

| 方案 | paths | anchors | bytes | **MSE↓** | **PSNR↑** | 白缝/白点 |
|---|---|---|---|---|---|---|
| **Vector Magic（bc.svg）** | 66 | **1253** | 56.3 KB | **8.07** | **39.06 dB** | 1 |
| vectorkit 描摹 1024（logo） | 30 | 795 | 23.0 KB | 55.45 | 30.69 dB | 0 |
| vectorkit 描摹 2048（logo） | 55 | 1939 | 54.7 KB | 26.88 | 33.84 dB | 0 |
| vectorkit 2048 + `vmde` 档 | 55 | 1412 | 41.1 KB | 24.46 | 34.25 dB | 6 |

**为什么还差 4.8 dB？（v5.1 归因结论）**：已逐个排除 —— 逐区域颜色拟合**中性**（VTracer 本身就在做）、
提高颜色精度**更差**、10 组样条参数**全在 ±0.13 dB 内**、分辨率已达**同源（双方均源自 2048²）**。
→ **剩余唯一解释：边界几何定位精度（亚像素）**。这也与结构观察一致：VM 用**更少的节点**
取得 **3 倍更低的 MSE**，差异只能在"边界落在哪里"。下一步见 PLAN 的 v5.2（亚像素边界重定位）。

**读数与结论**：

1. **差距已量化：PSNR +4.81 dB（MSE 3.0 倍），而且 VM 用的节点更少**（1253 vs 1939）、
   体积相当（56.3 KB vs 54.7 KB）→ "智能节点分配"不是宣传，是**可测的真实差距**。
2. **VM 的节点几乎全是三次曲线**（`C` 1126 / `L` 仅 36 / `M` 91 / `Z` 66）；我们的 `L` 占比明显更高。
3. **VM 按区域拟合颜色**：同一张图里出现 `#fffffd`/`#fffffe`/`#fefefe` 等**多个"近似白"变体**
   → 它**不做调色板量化**，而是**逐区域解出最优色**（贝叶斯 MAP 的直接产物）。
4. **结构差异**：VM 是 **66 path / 54 `<g>`（按 RGBA 一色一组）**，并把大量子路径塞进**复合路径**；
   我们是"一个形状一条 path"。
5. **白缝不是我们的短板**（1 vs 0–6）。
6. **分辨率有效但补不上差距**：我们 1024→2048 得 PSNR +3.15 dB；**即便同为 2048 原生描摹，仍差 4.8 dB**
   → 差距在**算法层**（亚像素边界 + 逐区域颜色拟合），不在分辨率、也不在节点数量。

## 五、刻意取舍（哪些差距是我们主动接受的）

| 取舍 | 我们的选择 | 理由 |
|---|---|---|
| 亚像素精度 | **暂不实现**，改为"提高描摹分辨率"逼近（×2 已让 PSNR +3.3dB） | 复刻需可微光栅化 + 迭代优化，代价高；分辨率是低成本近似 |
| 节点自动最优 | 关闭 `simplify` 默认；保留为可选 | 实测在本图**降质**，不拿质量换体积 |
| 无缝边界 | 提供 `vmde` 档（cutout），不设为默认 | 1× 下白缝略增（11→40），需用户按图选择 |
| 批量/编辑 | 未做 | 当前定位是"单张、快速、本地、免费"，先做深不做宽 |
| 引擎大图上限 | 用 8M 像素安全预算兜住 | **实测 14.7M 像素时 VTracer 输出退化**（大面积白色覆盖），必须防 |

## 六、一句话总结

> **Vector Magic = 用贝叶斯 + 共轭梯度"反解抗锯齿"的原生重型引擎；vectorkit = 用线性引擎 + 参数化后处理的浏览器轻量工具。**
> 前者赢在**亚像素精度与自动决策**，后者赢在**零安装、纯本地、免费、可离线**。
> 我们能低成本逼近的路径是：**提高描摹分辨率 → 再上"重栅格化误差优化"（v4.8 计划）**；
> 不该追的是：**脱壳复刻它的算法**（不可能、且不合法）。
