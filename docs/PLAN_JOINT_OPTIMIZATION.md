# C 方案计划：联合优化 / 可微光栅化（逼近 Vector Magic 的唯一正解）

> 状态：**已被取代（superseded，v6.5 标注）** —— 本方案的核心结论在后续实测中被推翻：
> v5.2 证明"逐点亚像素重定位"安全范围内 0 收益；v5.6/v6.1 找到**正确机制**
> （覆盖率 α + marching squares 半边 + 曲线拟合）。
> **现行方案见 `PLAN_PARALLEL_ENGINE.md`**（已落地 P0/P1/去碎片化）；本文件仅作历史留存。
> 依据：v5.0 同图对照（VM 高 +4.81 dB，实测）→ v5.1 归因（颜色/参数/分辨率全部排除）
> → v5.2 逐点亚像素重定位实测失败（安全范围 0 收益）
> 目标：把与 Vector Magic 的差距从当前 **−1.7 dB 左右**继续压低
> 日期：2026-10-13

## 一、为什么只剩这一条路（前情提要，都有实测支撑）

| 已排除的手段 | 实测结果 |
|---|---|
| 逐区域颜色拟合 | 中性（VTracer 本就在做） |
| 提高颜色精度（`colorPrecision` 8） | 更差（色块碎片化） |
| 样条参数调优（corner/length/splice/polygon，10 组） | **±0.13 dB 内**，无法缩差距 |
| 提高描摹分辨率 | 有效但已到同源（双方均源自 2048²） |
| **逐点亚像素边界重定位** | 安全范围内**只有 5 个锚点合格、收益 ≈0.00 dB**；不安全范围内有害 |
| `simplify` 曲线简化 | 换体积/平滑，不换质量（甚至降 MSE） |
| `filterSpeckle` 去噪 | **有效**（v5.3 已用于默认：14→8，bc +2.86 dB），但它是"细节 ↔ 碎块"的同一个旋钮，两端不可兼得 |

**结论**：以上全是"**局部/单参数**"手段。VM 的核心机制是**对全体边界联合求解**（Diebel 2008 的"连续阶段"：
非线性共轭梯度；DiffVG 把它实现为可微光栅化）——这是**唯一还没试过、且理论上正确的方向**。

## 二、要解的问题（形式化）

把矢量图记为参数 `θ`（所有子路径的锚点坐标 + 控制柄），定义

```
L(θ) = Σ_pixels  ρ( Rasterize(θ) − Target )        ← 数据项（像素误差）
      + λ₁ · Nodes(θ)                              ← 节点数惩罚（避免无限加节点）
      + λ₂ · Smoothness(θ)                         ← 曲率/二阶差惩罚（抑制抖动）
      + λ₃ · SharedBoundary(θ)                     ← cutout 下"共享边界只存一份"的约束
```

求 `θ* = argmin L(θ)`。**这与我们现有的"一次性拟合"是完全不同的问题类别。**

**关键取舍**：我们**不需要写出解析梯度**。浏览器里可以用**有限差分**：
对某个控制点 `θᵢ` 试 `θᵢ ± δ`，各重渲染一次、算 `L`，得到数值梯度。这正是 DiffVG 论文里
"finite difference 对照"的可行子集 —— 代价是**每次迭代要多次重渲染**。

## 三、分阶段实施

### P0 — 最小可行原型（目标：证明能显著降 L）

1. **渲染器**：复用现有 `vendor/resvg.mjs`（`renderRgba(svg, w)` 已存在于 `app.js`）。
2. **参数集（第一版）**：只优化**锚点坐标**（不含控制柄），且**只取 L 贡献最大的前 K 个锚点**
   （用 v5.2 已验证的"5×5 邻域误差和"打分）→ `K=32`。
3. **梯度**：对每个锚点做 8 方向 × 2 步长（±0.25px、±0.5px）的有限差分，取最优方向。
4. **约束（必须）**：
   - **角点保护**（转角 > 40° 不动）—— v5.2 的教训；
   - **段长守卫**（相邻段 > 24px 不动）—— v5.2 的教训：刚性平移会把整段曲线推走；
     *或*改用"只移锚点、不动控制点"的**局部重参数化**（见 P1-2）；
   - **fail-safe**：每轮整体 L 不下降就回滚（`refine.js` 已实现该模式）。
5. **验收**：`bc.png 2048²` 上，从当前默认（≈36.5 dB）出发，**PSNR 提升 ≥ 0.5 dB** 才继续；否则停。

> 复用资产：`refine.js`（坐标下降 + fail-safe + `shiftAnchor`）、`colorfit.js`（owner map）、
> `subpixel.js`（法线采样 + 各跳过策略）。P0 基本是在 `refine.js` 上**加强标签集与步长策略**。

### P1 — 让它真正"划算"

1. **局部渲染**：resvg 无法局部渲染 → 改用 **Canvas Path2D 局部重绘**：
   只重画"被改动的子路径"的**包围盒**区域，误差也只在该区域统计。
   预期把单次试探成本从 ~15ms 降到 ~1–3ms（**这是可行的关键**）。
2. **控制柄也参与优化**（锚点+两柄共 6 维/点），并对高曲率处做**保角约束**。
3. **多尺度 coarse-to-fine**：先在 1/4 分辨率上粗调（快），再在原分辨率精调（准）。
4. **共享边界一致性**：对 cutout 结果，**不要逐路径独立优化**（v5.2 已证明会撕开边界）；
   要么先转成 stacked 再优化，要么建立"共享段 → 同一参数"的映射（工程量大）。

### P2 — 产品化（可选）

- 时间预算档（1s / 3s / 8s / 20s），实时显示"当前 PSNR / 已提升多少"；
- 作为「**vmde 最高保真**」预设的**可选开关**（默认关闭，与 v5.0 的 refine 一致：实验能力默认关）；
- 若 P1 的局部渲染成功，可考虑做成"点一下，等几秒，更好一点"的按钮。

## 四、验收标准（硬门槛）

| 项 | 门槛 |
|---|---|
| PSNR 提升（bc 2048²，同口径 1024²） | **≥ +0.5 dB** 才考虑上线；≥ +1.0 dB 才有产品价值 |
| 耗时 | P0 ≤ 30s；P1 目标 ≤ 8s（可配置预算） |
| 稳定性 | 任意输入**不得**比不优化更差（fail-safe 回滚） |
| 体积 | 节点增长 ≤ +50%（避免"靠堆节点换精度"） |
| 回归 | `npm test` 全过；Bon Cho + bc 双图不得退化 |

**当前基线（便于对照）**：bc 2048² 同口径 → 默认档 **36.53 dB**（去噪8 + simplify1 + cutout），
VM **39.06 dB**（差距 **−2.5 dB**）；不限 simplify 时我们最好 37.11–37.35 dB。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 迭代太慢、浏览器里不可用 | P1-1 局部渲染是**前置条件**；先做 P1-1 再谈 P0 之外的能力 |
| 发散/过拟合到噪声 | 数据项加 **ΔE/结构项**；λ₁ 节点惩罚；早停；fail-safe |
| 破坏形状（角被磨圆、直线被扭曲） | 角点保护 + 直线段锁定（`snapAxisAlignedEdges` 思路） |
| cutout 共享边界被撕开 | **不在 cutout 上做逐路径几何优化**（v5.2 实测：对 cutout 强开 `edgeSmooth` 会让 MSE ×46） |
| 投入产出比不划算 | P0 有明确"≥0.5 dB 才继续"的门槛；不达标就停，把力气留给别的方向 |

## 六、与已否决方案的关系

- **不是**"再调参数"（v5.1 已证明参数空间是平的）；
- **不是**"逐点修正"（v5.2 已证明安全范围无收益）；
- **是**"全局联合优化" —— 唯一与 VM 同源、且尚未尝试的路径。
