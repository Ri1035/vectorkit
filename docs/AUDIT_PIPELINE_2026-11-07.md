# 后处理管线自检与冲突修复（v8.6 · 2026-11-07）

> 触发：用户要求「自检整个项目所有参考文件，是不是太多技术揉合导致多方不协调，再次审查 bug 并优化」。
> 结论先说：**不是技术太多，而是 12 个后处理步骤缺少统一契约**（谁改几何 / 谁改颜色 / 谁改渲染属性 / 先后顺序），
> 其中 5 处是真正的冲突，已在本版修复并给出实测证据。

代码模块也做了盘点（`scripts/build.mjs` 的 `DEV_ONLY`）：

| 类别 | 模块 | 说明 |
|---|---|---|
| 生产链路 | `app.js` `preprocess.js` `denoise.js` `matte.js` `svg-compat.js` `svg-enhance.js` `merge-paths.js` `refine.js` `eps-export.js` `dxf-export.js` `cmyk.js` | 全部被 `app.js` 引用 |

结论：**没有「多套技术在线上同时生效」**；不协调来自同一套链路内部的顺序与契约，而不是模块数量。

## 三、已确认的缺陷与根因

### B1 · 近似色合并后大面积白洞（最严重）

- 现象：开启「近似色合并」后 PSNR 33.22 → **25.20 dB**，大片区域变透明。
- 根因：`mergeSameColorPaths` 用 `ensureClosed()` 判断能否并集；**复合路径里只要有一个退化子路径
  （≤2 个锚点）就整条判为不可合并**，但回插阶段仍按「颜色分组」整组删除 → 元素被删掉却没有并入并集。
- 复现：bc-test 中 `#492620` 组 4 条路径，其中 1 条含 33 段 + 2 段的两个子路径 → 该条被排除，
  另 3 条并成 3 个子路径，随后第 4 条被删除 → 整块深色区域消失（15048 个白像素）。
- 修复：退化子路径单独剔除；回插只删「真正参与并集」的元素（`els` / `firstEl`）。
- 结果：PSNR 回到 **33.23 dB**，白洞消失（最小复现从 1 条 3 子路径 → 1 条 4 子路径）。

### B2 · 先合并再剥背景 → 白色细节被一起删掉

- 白色背景与眼白/高光同色；合并先把它们并成一条复合路径，`dropBackgroundLayer` 再删「节点最多的那条」，
  眼白/高光随之消失。
- 复现（合成图）：旧顺序（合并→删背景）白色细节 0 条；新顺序（删背景→合并）白色细节 1 条。
- 修复：背景剥离提前到 SVGO 与同色合并之前；并增加「包围盒 ≥90% 画布」判据，避免误删插画里的大块白色主体。

### B3 · 边界吸附把复合路径压成单条路径

- `snapAdjacentBoundaries` 重建 `d` 时只写一个 `M`，后续子路径全部变成 `L`/`C` 连到前一条上。
- 复现：53 条合并结果里 **22 条复合路径全部丢失子路径结构**（M 数从 7/5/12… 全变成 1）。
- 影响：cutout 模板跳过该步骤所以未暴露；一旦用 stacked（易编辑/线稿）就会破坏挖孔与色岛。
- 修复：按子路径重建 `M`，按各自的 `Z` 闭合。复测：0 条结构变化。

### B4 · 小图自动 ×2 上采样被裁掉 3/4（既有 bug，非 v8.5 引入）

- 引擎输出没有 `viewBox`，`ensureSvgSize()` 只拿到「原始尺寸」就补了 `viewBox 0 0 原宽 原高`，
  但几何在 2 倍网格上 → 只显示左上角 1/4。
- 实测（原图 → 修复前 → 修复后）：winter 593² **10.62 → 30.08 dB**；
  sunflower 475² **9.67 → 24.83**；mandala 366² **8.41 → 19.28**。
- 修复：`ensureSvgSize` 分离「显示尺寸」与「几何网格」，上采样时 `viewBox` 用放大网格；
  老软件兼容/ EPS / DXF 均按 viewBox→width 比例换算（DXF 原先会输出 2 倍物理尺寸）。

### B5 · 关掉「同色路径合并」仍会合并

- 勾选状态只控制整段后处理是否执行；只要「碎块清理」还开着，`mergeSameColorPaths` 仍会做布尔并集。
- 修复：新增 `merge` 参数；为 false 时只逐元素做碎块清理/边缘平滑。页面 1/3 均传入开关值。

### B6 · 描边补偿与颜色还原打架

- 描边补偿把 `stroke` 设成当时的 `fill`；随后背景色/保护色还原只改 `fill`，描边保留偏移色（shade 30），
  会在元素边缘露出一圈明显异色。
- 修复：两个还原函数在改 `fill` 时同步把「等于旧 fill」的 `stroke` 一起改回。

### B7 · 其他顺序问题

- `unifyEqualRadiiInSvg` 在 `snapAdjacentBoundaries` 之后运行，会把刚吸附好的锚点再次移开 → 已对调。
- 两个几何后处理（半径统一/边界吸附）原先在「合并关闭、碎块清理开启」时也会静默运行 → 现在只在合并开启时运行。

## 五、默认值决策（已执行）

近似色合并改为**按模板类型下发**，启动默认开启：

| 模板 | fillSnap | 理由 |
|---|---|---|
| daily / lean / artwork / smooth / photo / editable | 开 | 插画/商品图，对象数降 44%–85%，PSNR 代价 ≤0.09 dB |
| tiny | 关 | 已用 48 色量化降色，再归并会二次损失颜色 |
| faithful | 关 | 该档定位「不改色、逐色还原」 |
| line | 关 | 黑白只有两色，合并无收益，反而损失抗锯齿过渡色 |

剩余风险：stacked 模板会把合并结果放在该组第一个元素的位置，若后续出现「移动单块后遮挡关系不对」，
需要再评估 z 序；cutout 模板不受影响（相邻面共享边界，并集只是消除内部缝）。

## 六、VM EPS 对照（v8.7）

用户提供 VM 导出的 `bc-test.eps`（BoundingBox 640²）与 `x.eps`（593×807）。
EPS 结构：`moveto / lineto / curveto / closepath / setrgbcolor / fill`，**无描边、无裁剪、无渐变**；
背景是一条带孔的大路径，前景按颜色逐块覆盖 —— 典型的「区域分区」结构。

### 结构对比（bc-test）

| 项 | VM | 我们（v8.6） | 我们（v8.7） |
|---|---|---|---|
| 填充块 | 49 | 53 | 108 |
| 子路径 | 82 | 113 | — |
| 曲线段 | 756 | 1144 | — |
| 节点总数 | 897 | 6713 | 6713 |
| PSNR | **36.73** | 33.04 | **33.31** |
| edgeCorr | **0.861** | 0.758 | 0.757 |

### 差距归因

1. **颜色（主因）**：平坦像素 MAE：VM 0.78 / 我们 1.60（bc）、0.46 / 4.21（winter）。
   VTracer 的 `layerDifference=32` 把相差 <32 的浅色带并掉；VM 保留。
2. **曲线效率（次因）**：VM 平均 9 条曲线/子路径、节点总数不到我们的 1/5；
   我们的锚点落在像素阶梯上，边角更多。
3. **拓扑**：VM 用「背景挖孔 + 逐块填充」保证无重叠；我们用叠加 + 同色描边盖缝。
   两者都能消白缝，但 VM 的结构在编辑器里更干净。

### v8.7 已做的调整

`colorPrecision 6→8`、`layerDifference 32→16`（四图 PSNR +0.27 / +3.44 / +0.66 / +0.33；
bc 白缝 7404→2212）。仍未追平的部分需要 Phase 3 的共享边界联合拟合，不在本轮实施。
